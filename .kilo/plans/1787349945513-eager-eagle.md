## Gap found and closed (commit made locally — NOT yet pushed)
The spec requires a `100x` button; the frontend sends `{ speed: "hyper" }`.
The backend `set_speed` rejected `"hyper"` (400) because
`backend/app/schemas/world.py` only declared `realtime|fast|ultra`, even though
the engine already defines `TimeSpeed.HYPER = 100` and `TimeManager` accepts
`speed_multiplier=100`.

Fix (commit `158393f` [TOAST], local only):
- `schemas/world.py`: add `HYPER = "hyper"` to `TimeSpeed`, add `"hyper": 100.0`
  to `TIME_SPEED_MULTIPLIERS`.
- `routers/world.py`: docstring notes `hyper=100x`.

Smoke test confirms `speed_multiplier=100.0` is accepted by the setter
(`max(0.1, v)`) and produces real time advance.
